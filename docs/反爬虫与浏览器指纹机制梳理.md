# 反爬虫与浏览器指纹机制梳理

> 梳理时间：2026-10-17
> 分支：`xhs-dating-research`
> 适用范围：以 XHS（小红书）管线为主，兼提其他平台的差异化实现

本项目反检测体系的总体思路是 **"用真浏览器，而不是伪装浏览器"**，在此之上叠加签名、行为随机化、IP 代理、风控响应四层防护。

---

## 1. 浏览器指纹层（核心防线）

### 1.1 CDP 模式接管本机真实浏览器

- **入口**：`tools/cdp_browser.py` (`CDPBrowserManager.launch_and_connect`) + `tools/browser_launcher.py` (`BrowserLauncher`)
- 自动探测本机安装的 Chrome/Edge（`browser_launcher.py:45` `detect_browser_paths`，覆盖 Windows/macOS/Linux 常见安装路径及 Beta/Dev/Canary），以远程调试端口启动后通过 CDP 协议连接。
- 效果：浏览器二进制、字体、插件、版本号全部来自真实本机环境，与 Playwright 自带 Chromium 有本质区别。
- 关键反检测启动参数（`browser_launcher.py:141-144`）：
  - `--disable-blink-features=AutomationControlled` — 去掉 `navigator.webdriver` 自动化标志
  - `--exclude-switches=enable-automation` — 排除自动化开关
  - `--disable-infobars` — 去掉 "Chrome 正受到自动化控制" 提示条
  - 其余：`--disable-ipc-flooding-protection`、`--disable-hang-monitor`、`--disable-prompt-on-repost` 等
- **复用已有浏览器**：`CDP_CONNECT_EXISTING = True`（`config/base_config.py:83`）时连接用户手动开启远程调试的浏览器（`cdp_browser.py:140` `_connect_existing_browser`），兼容 Chrome 136+ 不暴露 `/json/version` 的情况（直接拼 `ws://localhost:{port}/devtools/browser`）。
- 登录态持久化：`SAVE_LOGIN_STATE = True` 时使用 `browser_data/cdp_xhs/` 作为 user-data-dir（`cdp_browser.py:250-263`），复用 profile 减少反复登录触发风控。
- 进程清理：atexit + SIGINT/SIGTERM 处理器兜底（`cdp_browser.py:47-95`），异常退出不留僵尸浏览器进程。

### 1.2 stealth.min.js 全局注入

- **注入点**：`media_platform/xhs/core.py:104`
  ```python
  await self.browser_context.add_init_script(path="libs/stealth.min.js")
  ```
- 持久化上下文与 CDP 上下文**都需要注入**，否则 `navigator.webdriver` 等自动化痕迹会暴露。
- 内容：puppeteer-extra stealth evasions 全量打包（2023-06 版本，约 176KB），抹掉 JS 层一系列指纹（`navigator.webdriver`、`window.chrome` 缺失、`permissions.query` 异常、插件/语言/平台伪装等）。
- 其他平台（douyin/zhihu）有各自的附加注入脚本 `libs/douyin.js`、`libs/zhihu.js`（用于签名而非反检测）。

### 1.3 UA 一致性（本分支定制改动）

- `core.py:448-449`：persistent context 下**不覆盖 user_agent**，让浏览器使用与自身版本一致的原生 UA。
  注释原文："覆盖会造成 UA 与浏览器指纹矛盾，容易被风控识别并撤销登录态"。
- `core.py:109-112`：页面加载后通过 `navigator.userAgent` 读取浏览器真实 UA，回填给 API 客户端（`core.py:417`），保证 HTTP 请求头与浏览器指纹一致。
- `core.py:67-69`：`__init__` 里的 UA 仅作占位默认值，`start()` 中必然被覆盖。

## 2. 请求签名层（XHS）

- **签名方案**：`media_platform/xhs/playwright_sign.py:33` `sign_with_xhshow`
  - 使用 `xhshow` 纯算法库（https://github.com/Cloxl/xhshow ，MIT License）本地生成签名头，**不再需要打开浏览器页面执行签名 JS**（老方案为 Playwright 页内调用 `window._webmsxyw`）。
  - 生成 `x-s / x-t / x-s-common / x-b3-traceid` 四个头（`client.py:118-123`）。
  - 依赖 `xhshow>=0.2.0`：该版本原生修复了 GET 请求 `a3_hash` 计算的 bug（[xhshow#104](https://github.com/Cloxl/xhshow/issues/104)），无需本地 monkey-patch。
- **编码一致性**：`client.py:198-205` `_build_query_string` 手工拼 query string，逗号不编码（`quote(value_str, safe=',')`），保证参数编码与浏览器行为一致，否则签名串与实际请求不匹配会被判非法。
- **其他平台**：
  - 抖音：`media_platform/douyin/help.py:37` 用 execjs 编译 `libs/douyin.js` 生成签名
  - 知乎：`media_platform/zhihu/help.py:50` 加载 `libs/zhihu.js`
- **HTTP 请求头基线**：`core.py:402-419` 构造完整浏览器风格请求头（`sec-ch-ua`、`sec-fetch-*`、`origin`、`referer` 等）。

## 3. 行为层（随机化与请求量控制）

### 3.1 随机抖动

所有翻页/详情/评论间隔均加随机抖动，去掉等间隔机器特征，共 4 处（`core.py:197-199, 234-235, 333-336, 379-390`）：

```python
page_sleep = random.uniform(config.CRAWLER_MAX_SLEEP_SEC, config.CRAWLER_MAX_SLEEP_SEC * 2.5)
await asyncio.sleep(page_sleep)
```

基准间隔 `CRAWLER_MAX_SLEEP_SEC = 2`（`config/base_config.py:140`），实际区间 2~5 秒。

### 3.2 探测后置（§13 风控整改，commit `7a15b5d`）

先做本地预过滤，只对通过筛选的"幸存作者"才发起主页探测请求，从源头降低触发风控的请求量。

### 3.3 评论级去重（commit `45ae7db`，阶段二）

管线阶段二引入评论级去重，减少重复请求。

## 4. 网络层（IP 代理）

- **IP 池**：`proxy/proxy_ip_pool.py:44` `ProxyIpPool`，供应商抽象（`IP_PROXY_PROVIDER_NAME`: kuaidaili / wandouhttp / static）。

  - `get_or_refresh_proxy` — 自动换新 IP

- ⚠️ **CDP 模式下 Playwright 代理不生效**：`cdp_browser.py:389-393` 有显式警告，需在浏览器/系统层配代理。

## 5. 风控响应层（识别封禁信号并分类处理）

核心在 `media_platform/xhs/client.py:153-196` `request`：

| 信号 | 识别方式 | 处理 |
|---|---|---|
| HTTP 401/403/429 | 状态码 | 抛 `PlatformAccessError` |
| HTTP 471/461 | 响应头 `Verifytype` / `Verifyuuid` | 识别为**验证码**，直接报错不硬闯 |
| 业务码 `IP_ERROR_CODE` | 响应体 `code` | 抛 `IPBlockError`（IP 被封）|
| 业务码 `SECURITY_LIMIT_CODE` | 响应体 `code` | 账号安全限制 → `PlatformAccessError` |
| 笔记不存在/异常 | `NOTE_NOT_FOUND_CODE` / `NOTE_ABNORMAL_CODE` | 抛 `NoteNotFoundError` |

**重试策略**（`client.py:127-133`）：tenacity 3 次、固定间隔 1s；但 `NoteNotFoundError` / `IPBlockError` / `PlatformAccessError` **不重试**——不可恢复错误硬重试只会加重风控记录。

**辅助工具**：
- 滑块验证码：`tools/slider_util.py` + `tools/easing.py`（滑动轨迹模拟），用于抖音滑块（`media_platform/douyin/login.py:177-198`，`#captcha-verify-image`）。
- 登录流程 CAPTCHA 检测提示：`media_platform/xhs/login.py:73`。
- 抖音验证码中间页检测：`media_platform/douyin/login.py:75`。

## 7. 已知薄弱点与改进方向

1. **`sec-ch-ua` 硬编码**：`core.py:411` 固定 `"Chromium";v="136"`，与本机真实浏览器版本可能矛盾——与 UA 矛盾问题同源，但该头尚未动态化。建议改为从浏览器实际版本生成。
2. **stealth.min.js 版本陈旧**：2023-06 生成，对新版 Chrome 的指纹检测（如 `userAgentData`、WebGPU 指纹）覆盖有限。可考虑用 puppeteer-extra 最新版重新生成，或引入补丁型方案（rebrowser-patches 等）。
3. **调试端口对外暴露**：`browser_launcher.py:128` `--remote-debugging-address=0.0.0.0` 允许远程访问 CDP 端口，本机局域网内有被其他进程/主机接管浏览器的风险。建议改回 `127.0.0.1`（除非确有远程调试需求）。
4. **CDP 模式代理不生效**：IP 层防护依赖代理池（httpx 客户端）与浏览器代理配置的一致性；若浏览器直连而 API 走代理，两侧出口 IP 不一致本身就是一个可检测特征。
5. **CDP 模式 `--no-sandbox`**：关闭沙箱降低隔离性，仅在 CDP 调试场景必要。
